# 3DGS 优化计划

目标是在保留场景细节和视角一致性的前提下，缩短首帧等待、降低渲染与存储开销，并持续修复使用中的问题。

## 优先级

| 优先级 | 方向 | 待验证事项 | 验收依据 |
| --- | --- | --- | --- |
| P0 | 正确性与稳定性 | 加载失败重试、快速切换场景、后台恢复、上下文丢失、模型和纹理释放 | 已验证资源回收、重叠请求隔离、缓存事件处理和评测迟到结果取消；已补充本地 HTTP 缓存、304、断连和默认 PLY 解压长度拒绝，已修复后台排序预算与取消等待；已补齐上下文丢失后的刷新和释放；原生后台限流、真实 CDN 与原地上下文恢复继续验证 |
| P1 | 加载与空闲开销 | 下载/解码/首帧分段计时、缓存与分块；按需渲染与后台暂停 | 已完成按需渲染、流式解压、错误头提前拒绝、尺寸去重和加载分段导出；已测静态发布包、新文档受控 HTTP 缓存、实际 gzip 字节及场景切换资源清理；进程冷启动、真实 CDN、内存峰值和分页仍待测量 |
| P1 | 性能测量 | 补充固定相机路径、排序等待、帧时间分布及可用的内存指标 | 同设备、同画幅、同相机路径，保留原始样本 |
| P2 | 渲染效率 | 排序、可见性剔除、LoD、SH 存储与 GPU 上传 | CPU/GPU 时间、P95、画质与显存成本同时报告 |
| P2 | 外观与稳定性 | 抗锯齿、缩放一致性、旋转跳变、漂浮物与细小结构 | 同视角 PSNR/SSIM、局部截图及漫游检查 |
| P3 | 压缩与训练 | 属性量化、渐进加载、剪枝、增密与训练参数 | 文件大小、解码耗时、训练耗时和质量变化 |

首先建立当前完整 SH3、关闭 LoD 的基线，再逐项引入可切换的实验设置。按需预览已经接入 Spark 的 `onDirty`。2026-10-25 的[绘图缓冲实验](DRAWING-BUFFER.md)未采用同时关闭两侧缓冲保留的方案：办公室 3DGS 没有稳定收益，Mesh GPU 查询时间上升。[加载分段](LOAD-TIMING.md)已接入评测页与导出；本地观测提示先分别检查高斯读取/解压及首帧准备，再做受控网络和缓存实验。仅调整高斯缓冲与不透明度边界仍为候选，不预设收益。

## 实验要求

[预分配解码缓冲](READ-BUFFER.md)的 gzip 收益不足，未采用。[SPZ3 格式对照](SPZ-FORMAT.md)减小体积和内存输入加载等待，但留出画质下降；[SH 属性对照](SPZ-ATTRIBUTES.md)、[8 位 SH 文件](SPZ-SH8.md)和[非 SH 诊断](SPZ-NONSH.md)进一步定位了方向颜色与不透明度误差。

现已完成 [SH8 + AP16 真实文件验证](SPZ-ALPHA16.md)：合计 12.47 / 8.90MiB，20 个画面完全复现恢复不透明度的诊断组合；附加解压/校验/恢复为 7.40 / 4.80ms，内存输入总等待低于 PLY。仍非原始模型无损，也不是冷加载结论。

[AP16 流式读取](ALPHA16-STREAM.md)现已接入[独立候选加载流程](PAIRED-MODEL.md)：配对及文件摘要检查、取消、迟到初始化清理和 PLY 回退均通过；30 个画面完全复现原始/候选控制，12 个模型各释放一次。默认查看器和旧画质/耗时夹具保持原流程。

[真实 HTTP 缓存实验](HTTP-MODEL.md)已验证本地缓存命中、ETag 304、旧版内容错配和连接中断。固定 URL 的旧 AP16 会连续触发回退；内容摘要版本 URL 恢复候选并保留缓存。20 项加载、36 个画面对照通过；未把 0B 正文当作加载完成或性能收益。

[受控 HTTP 加载](PACED-MODEL.md)已完成 32 个串行样本：5MiB/s 正文限速、每请求服务器等待 40ms、热渲染器/WASM；候选缓存未命中等待缩短 77.4% / 78.3%，命中时缩短 45.0% / 44.9%。52 个画面一致，但候选初始化本身较慢，不能宣称解码加速。计时终点为排序稳定后的绘制提交，不是屏幕呈现。

[默认 PLY 长度校验](PLY-SIZE.md)已接入：超长、短包与缺失长度在 Spark 初始化前拒绝，4 组文件和 10 个画面不变。没有把模拟源供给量当作网络或内存峰值收益。

[后台排序恢复](SETTLE-VISIBILITY.md)已验证：隐藏不消耗 15 秒可见时间预算，取消不依赖下一帧；两场景各模拟隐藏 16 秒恢复，10 个原始画面不变。原生标签页限流和系统睡眠仍待验证，加载报告保留墙钟等待。

[PLY 分块输入](STREAM-INPUT.md)已完成 16 个热运行时样本与 36 次像素检查；单次输入限为 1MiB，但没有稳定初始化收益，也未测峰值内存。第二块读取失败的一秒观察窗口内，Spark 初始化仍 pending、reader 锁未释放；暂缓采用，先核实流错误传递、Worker 作业结束与恢复，默认保留 `fileBytes`。

[性能评测取消](BENCHMARK-CANCEL.md)已补齐排序准备、帧采样与查询收尾的信号传递；7 项取消检查、18 次像素控制和 107 项测试通过，已创建的 3 个查询均删除。原生后台限流、系统睡眠和实际显存回收仍待验。

[GPU 计时异常恢复](BENCHMARK-QUERY.md)已修复活动查询遗漏：四项真实 WebGL2 异常和四次完整重试通过，12 份重建画面与基线一致。分配空值保留缺失 GPU 样本，不影响 CPU 记录；此项为计时正确性修复，非渲染提速。跨浏览器时间戳可靠性、自然设备故障及实际显存回收仍待验。

[上下文丢失收尾](CONTEXT-LOSS.md)已完成六项桌面故障回归、一次窄屏检查与两次刷新恢复；迟到操作不能复活页面，排序 Worker 释放，12 份留出画面不变。恢复策略为整页刷新，未验证自然 GPU 重置或原地上下文重建；解析 Worker 池的实际回收与显存峰值继续待测，不记为性能提升。

[画质帧等待取消](QUALITY-FRAMES.md)已修复，10 项取消检查及 18 份评分输入摘要对照通过；恢复阶段取消也丢弃报告。初测和生产检查中的首张照片微小评分波动保留输入摘要继续调查；原生后台与睡眠仍待验证。

[参考照片等待取消](IMAGE-DECODE.md)已补齐评测与查看器生命周期信号，8 项浏览器检查和两次原生 JPEG 停流取消通过；原生 decode Promise 短时仍可能 pending，不将调用方结束当作解码器或内存同步回收。12 份重建画面摘要不变，office 首张参考图变化在旧版也复现。

[参考像素诊断](REFERENCE-PIXELS.md)已保存原尺寸与缩放 RGBA，复现的 office 波动在原尺寸读回时已存在；直接开启 willReadFrequently 会改变六张照片和评分，暂不采用。72 组矩阵、12 次视角评分与恢复流程已记录。独立 RGB 解码对照已完成，见下文；实际浏览器解码/颜色路径仍待直接观测。如需改取样方式，明确版本化评分协议并重建基线，暂不缓存参考图。

[独立解码控制](REFERENCE-DECODE.md)已完成：Pillow/libjpeg-turbo 与既有频繁读取结果逐字节一致，PNG 控制复现 office 的恢复状态；36 次原尺寸 PNG 读回匹配，但缩放设置仍产生差异，PNG 字节数为 JPEG 的 4.02 倍。暂不换图或继续重复同一矩阵。后续模型/渲染优化先核对输入摘要；固定解码与重采样作为独立评分协议候选，浏览器内部路径和跨浏览器一致性尚未确认。继续推进原计划中的冷启动、峰值内存与候选初始化成本。

线上一次未受控加载出现 332.24s 等待，读取阶段占主要部分，见[发布检查](QUALITY-FRAMES.md#线上发布检查)；优先核对真实 CDN 与浏览器缓存，不能仅凭这次观测归因于代码或解码器。

[加载取消与重试](LOAD-CANCEL.md)已补齐页面入口：10 项延迟读取/解析/首帧检查、两次真实 HTTP 停流取消及重试通过，6 个留出像素摘要不变。取消后可操作不等于底层解析同步停止；真实 CDN 等待成因与缓存诊断继续待查，不引入固定下载超时或自动重试。

[新文档首次初始化](RUNTIME-INIT.md)已完成 36 个样本与 52 次像素对照；复用 Worker 后候选仍较慢，优先分解 SPZ 解压、属性转换与峰值内存，不直接增加常驻预热。该实验预载输入，没有完成整页/进程冷启动或独立 WASM 计时；失败回退耗时也仍待测量。继续分别记录 HTTP 缓存和运行时状态。真实 CDN、清单跨版本一致性、304 元数据更新与重启后的磁盘缓存继续待验。暂不搜索其他位宽或替换默认资源；线上保留完整 SH3 的 PLY 模型。

[候选配对并行读取](PARALLEL-PAIR.md)已验证并接入独立候选加载器：32 个串行对照样本、52 次候选像素对照、六张留出评分和两次原始回退画面全部通过。每请求独立限速条件下未命中等待减少 158 / 126ms，热缓存未见明显收益；[共享总带宽上限实验](SHARED-PAIR.md)已完成 16 个样本，同条件总等待减少约 71 / 58ms；实际供给速率低于上限，未推广为真实网络收益。真实 CDN 和缓冲重叠的峰值内存仍待测。继续分解 SPZ 解压与属性转换，不把并行网络收益写作解析加速，默认页面仍用 PLY。

[相同 SPZ 属性的容器对照](SPZ-CONTAINER.md)已完成：32 个正式样本中，stored gzip 初始化中位数减少 47.45 / 37.85ms，52 次画面一致；文件增大 55.5% / 68.5%，暂不发布该格式。容器路径值得优化，但差值包含分块、传递和分配，不能视作纯解压 CPU 时间。下一步测独立原生解压/属性转换适配、取消与缓冲峰值；裸 v3 不能直接传入 Spark 的 v4 NGSP 分支。KISS-GS 图像编码保留为待核验候选，暂不扩大位宽或训练实验。

[SPZ v4 同属性对照](SPZ-V4.md)已完成：32 个正式样本中，文件减少 8.8% / 10.2%，初始化中位数增加 16.95 / 10.80ms；36 组属性与 52 次画面一致。当前 Spark 串行 ZSTD 路径没有初始化收益，暂不替换默认格式；弱网络下的端到端收益仍未验证。参考 C++ 原生多流并行与 Emscripten/Spark 串行实现分开记录，下一步优先剖析解压、属性消费和峰值缓冲；有分段证据后再考虑适配，接入前补齐 HTTP、取消和回退，不重复扫描压缩级别或训练参数。

[原生解压适配](SPZ-NATIVE.md)已完成：32 个正式样本中，计入原生展开和 stored 容器构造后，总等待中位数只减少 0.10 / 0.30ms，暂不接入；36 组属性与 52 次画面一致。已排除把 Spark 初始化单列节省当作总加载收益的误判。下一步优先直接剖析 Worker/WASM 解压、属性消费、结果缓冲和传递，再评估避免重复容器消费的接口；峰值内存、HTTP、取消与失败回退仍为接入前条件，不继续重复容器变体或预热扫描。

[Worker / WASM 分段](WORKER-PROFILE.md)已完成：32 个正式样本、40 组跨文档属性和 72 次画面摘要一致；push 占 handler 中位比例 99.3% / 99.8%，结果收尾与消息往返余量很小。插桩总等待增加 3.90 / 8.40ms，工具仅用于诊断。下一步在独立固定版本 Rust/WASM 构建中拆分输入复制、gzip 消费与属性打包/JS 写回，并校验插桩扰动；结果导出暂降优先级，不把 push 当作纯 inflate。已观测到的 25.5625MiB 仅为线性内存容量，JS 结果缓冲和真实峰值另测，默认模型不变。

[WASM 数组边界](WASM-IMPORTS.md)已进一步计量现有二进制：32 个正式样本中，接口函数体累计为 4.40 / 3.50ms，复制流量 137,345,116 / 105,201,327B；40 组属性、72 次画面一致。Spark 已使用批量 set，暂不移植 Niantic 的逐元素改批量补丁，也不把函数体计时当全部复制成本。该实验尚无 Rust/WASM 编译工具链，后续已完成固定构建和内部分段，见下文；不重复数组导入矩阵，不改生产模型。

[固定构建与 WASM 内部分段](WASM-INTERNAL.md)已完成：Rust 1.99.1 / wasm-bindgen 0.2.117、固定源码与 Cargo.lock；80 组属性、144 次画面一致。SH 阶段 73.75 / 57.10ms，约占 poll 属性处理 79%，比 gzip 写入/刷新更值得优先定位。下一步在独立无计时构建中验证 SPZ 离散 SH 的共享指数计算，覆盖零值、正负、幂次和舍入边界，保留 #465 的向上取整语义并要求完整属性位级一致。当前尚未独立测量 encode_ext_rgb；不把整个 SH 阶段归给该函数，不重复构建基线或压缩容器矩阵。默认 PLY 不变，通用输入、HTTP、取消回退和峰值内存仍需另验。

[SH 离散指数编码](SH-GRID.md)已完成独立无计时构建对照：初始化减少 31.85 / 23.75ms（21.40% / 21.02%），40 组属性、72 次画面及全部 16,777,216 个离散编码组合一致。保留非网格最大值的原路径，未改变默认依赖与资产。后续已完成通用 PLY 对照并发现回归，改为 SPZ 专用入口，见下文；原通用判断方案不再建议接入。编码语义假设已有验证，不重复原分段或压缩容器矩阵；不把总等待差值全部写作编码器 CPU 时间。

[SH 编码入口分流](SH-SCOPED.md)已完成三组串行对照：通用判断使 PLY 初始化增加 5.55% / 9.66%，专用入口消除观测到的回归，SPZ 初始化仍减少 20.28% / 20.24%。96 个正式样本、120 组属性、216 次画面一致；WASM 增加 4,237B。后续已完成专用构建的本地 HTTP 正确性、初始化取消与 404 回退，见下文；冷启动、真实 HTTP 端到端耗时和峰值内存仍待验证，再决定是否接入；不继续使用通用网格判断，不重复既有分段或矩阵。Compact Neural Appearance 的训练与属性布局另列研究候选，当前不启动训练或更换 SH 格式。
