# 照片条的下载量与清晰度

照片条中的图像占 60 × 42 CSS 像素。旧版为每个按钮读取长边 1024 像素的评测照片。现在打包场景时，Pillow 11.3.0 从已保存的参考 JPEG 等比例缩到长边 200 像素（Lanczos，JPEG 质量 90）。照片条读取清单中的 `thumbnailUrl`，旧清单沿用 `url`。原照片对照和留出评测都读取 `url`。[打包实现](../scripts/prepare_scenes.py) · [逐图记录与渲染摘要](benchmarks/photo-thumbnails-2026-11-25.json)

## 浏览照片条

在 Apple M5、macOS 26.5.1、Chromium 156.0.8078.4 上串行打开 Vite 的本地生产预览。基线为 `87515e3`。每个版本使用新浏览器上下文，桌面视口 1440 × 1000、DPR 1，先载入 pipes，再切换到尚未访问过的 office。逐个滚动到照片按钮，等待图片解码；统计该场景 JPEG 在 Resource Timing 中的 `encodedBodySize`。表中不含 HTTP 头、HTML、清单或模型下载。

| 场景 | 导航图片请求数（前后相同） | 旧照片条 | 新照片条 | 减少 | 首次点开照片 01 的额外下载 |
| --- | ---: | ---: | ---: | ---: | ---: |
| pipes | 14 | 2,219,935 B | 107,095 B | 95.18% | 159,332 B |
| office | 26 | 3,296,464 B | 165,329 B | 94.98% | 131,949 B |

旧版浏览完整条后，点开原图直接命中缓存。新版在点开前没有请求参考 JPEG，点开后两个画布上的原图共用一个请求，同页再次打开同一张也未增加网络传输。若依次查看全部原图，还会下载完整参考照片集。发布包新增 272,424 B 缩略图，两份清单合计增加 1,560 B（压缩前）。照片条在模型就绪后创建，本次没有测首帧或真实 CDN 的耗时。

390 × 844 的窄屏评测页也覆盖了全部 40 个按钮、末张视角选择和原图对照，完整照片条的请求数与字节数相同。用既有清单打开新版本，两场景均能从原照片显示全部按钮。

## 导航图的画质

对每张图分别用 Pillow `ImageOps.fit` 居中裁切，用 Lanczos 将参考图与缩略图缩放到同一尺寸。下表是逐照片等权均值。PSNR 取全图 RGB，SSIM 取 RGB 三通道、11 × 11 有效窗口、σ=1.5。180 × 126 一列衡量三倍像素密度下的图像细节，属于离线采样。

| 场景 | 60 × 42 PSNR / SSIM | 180 × 126 PSNR / SSIM |
| --- | ---: | ---: |
| pipes | 42.89 dB / 0.9952 | 35.70 dB / 0.9688 |
| office | 45.15 dB / 0.9956 | 39.11 dB / 0.9755 |

同一桌面位置的办公室照片条截图可查看编号、蓝色留出标记和管线细节。[原照片作导航图](images/photo-strip-baseline-2026-11-25.png) · [专用缩略图](images/photo-strip-preview-2026-11-25.png)

## 核对参考图与重建

40 张参考 JPEG、四个模型与基线逐字节一致。剔除新增的缩略图字段后，两份清单与基线内容一致，包括来源、授权、相机内外参和训练/留出划分。用同一 Pillow 版本从这些参考 JPEG 重新生成，40 张缩略图全部字节一致。

在原版与新版评测页使用相同设置串行评分。pipes 使用 2 个留出视角、768 × 505，3DGS 与 Mesh 的平均 PSNR / SSIM 分别为 16.2689 dB / 0.7309 与 13.4536 dB / 0.5431。office 使用 4 个留出视角、768 × 500，分别为 18.9534 dB / 0.8390 与 13.3466 dB / 0.6103。两个版本的六个视角逐项一致。两场景首个留出视角和自由查看中相同鼠标拖动后的双画布像素摘要均与基线一致。
